# 剧场整合设计文档

> 日期：2026-08-06
> 状态：待用户评审
> 范围：圆桌 + 故事机器 整合为"剧场"，并增强角色/世界观/Skills/战斗/幕后聊天能力

## 1. 背景与目标

当前网站将「圆桌」（多席位讨论）与「故事机器」（角色对演）作为两个独立入口，功能高度重叠（同一批人物库角色、同样的轮次/暂停/注入/模型切换），维护成本高、入口繁杂。

目标：

- 合并为单一「剧场」入口，讨论与演绎作为剧场内的两种模式。
- 保留并强化三我情绪算法（核心，每轮演算影响行为）。
- 角色卡增强：类型标签、身体素质五维、能力、装备道具。
- 引入「世界」概念，用世界观约束剧情不崩坏。
- Skills 作为**写作风格规范**复用现有系统，控制角色讲话时机与旁白输出。
- 战斗场景中「文字演绎 / 数值判定」比重可调（专用滑块，默认 70/30）。
- 开演前 AI 预读取（世界观/角色/装备/Skills），读完生成共识摘要才开演。
- 支持直接输入（导演注入）与幕后 AI 聊天窗口。

## 2. 整体架构

```
剧场（单一入口，替代圆桌 + 故事机器）
└── 世界（世界观 + 角色集合 + 装备库 + Skills 挂载）
    ├── 开演前：AI 预读取 → 共识摘要（读不完不开演）
    ├── 讨论模式（原圆桌）：主持人调度、轮次、结论
    ├── 演绎模式（原故事）：旁白 + 四通道 + 导演注入
    │    └── 战斗场景：文字演绎 ↔ 数值判定 比重滑块（战斗中可调）
    ├── 直接输入（导演注入 / 突发事件 / 指定行为）
    └── 幕后聊天（与 AI 讨论剧情、补设定、指挥演出）
```

导航：`圆桌`、`故事机器` 两个 tab 合并为 `剧场`。

## 3. 世界系统（保证剧情不崩）

每个「世界」是一份约束文档 + 元数据：

```json
{
  "world_id": "wx-xxxxxxxx",
  "name": "天界",
  "worldview": "世界观正文（规则、力量体系、禁忌、人物关系、已发生剧情）",
  "skill_ids": ["world-style-noir"],        // 挂到世界的写作风格 Skill
  "character_ids": ["...", "..."],
  "created_at": "...",
  "updated_at": "..."
}
```

规则：

- 所有演出/讨论都在一个世界内完成；角色卡必须属于某个世界。
- 世界观作为 system context 注入每个角色的 LLM 调用，约束 AI 不产出世界观外的设定。
- 已发生剧情追加到世界观（防前后矛盾），由导演注入或演绎结果自动追加。
- 世界可挂 Skills（如「世界观防崩坏」「暗黑文风」），全场生效。

## 4. 角色卡（增强）

```json
{
  "character_id": "abc123",
  "name": "沈默",
  "types": ["fight", "plot"],               // 战斗型 / 剧情型 / 对话型（可多选）
  "base_ratio": {"id": 33, "ego": 44, "superego": 23},  // 三我占比（情绪算法核心）
  "traits": [...],                          // 性格特质（影响情绪偏移）
  "events": [...],                          // 重大事件（持续影响）
  "stats": {"力量": 78, "敏捷": 65, "体质": 70, "智力": 82, "精神": 58},  // 身体素质五维
  "abilities": [{"name": "伞刃精通", "level": 3}],   // 能力/专长
  "equipment": [{"name": "青骨伞", "effect": "力量+5", "slot": "武器"}],  // 装备道具
  "skill_ids": ["style-taciturn"],          // 挂到角色的写作风格 Skill
  "emotion_state": {"anger": 0.62, ...},    // 当前情绪（每轮演算）
  "pressure": 47,                            // 压力值
  "memory_logs": [...],                      // 跨会话记忆日志
  "model_name": "zhipu:glm-4-flash"          // 模型选择
}
```

### 4.1 情绪算法（保留为核心）

- 每轮先演算情绪再行动：当前情绪影响发言用词、动作倾向；重大事件触发情绪偏移与三我占比重配。
- 情绪不直接生成剧情，仅作为行为倾向与战斗判定修正（愤怒 + 力量、- 理智；胆怯 + 逃跑倾向）。

### 4.2 五维与能力

- 五维默认：力量 / 敏捷 / 体质 / 智力 / 精神（名称可在设置中自定义）。
- 能力（技能/专长）带等级，战斗判定时提供加值。
- 属性与能力是「判定参考」，不直接生成剧情。

### 4.3 装备道具

- 角色卡新增装备栏：武器/防具/道具，字段含名称、效果、槽位。
- 战斗中装备影响判定（如武器力量 +5）。

## 5. Skills = 写作风格规范（复用现有系统）

不重做 Skills 系统，复用现有 SKILL.md 存储、CRUD、渐进式披露机制。**剧场内的定位：写作风格规范**，控制 AI 怎么写。

- **挂给角色**：控制该角色的讲话时机与说话方式。示例 SKILL.md 内容：
  - 「沈默惜字如金，只在对方说完后停顿两秒才接话」
  - 「林晚爱抢话，经常打断别人，但从不正面回答问题」
- **挂给世界**：控制旁白输出。示例：
  - 「旁白跟随林晚视角，环境渲染浓重，冷峻文风，多用短句」
  - 「描述战斗时以动作细节为主，心理描写从简」
- 剧场面板提供「技能」区：调取现有 Skills 列表、勾选挂载到角色/世界、点击编辑（复用现有编辑器）。
- 演出时，角色的 Skill 内容注入角色 prompt；世界的 Skill 注入旁白与全局叙事 prompt。

## 6. 战斗场景与比重调节

- 演绎模式下可选择「战斗场景」。
- 战斗界面提供专用滑块：**文字演绎 ↔ 数值判定**，默认 70% / 30%，战斗中可随时调节。
  - 偏文字：AI 自由描写战斗过程，五维/能力/情绪仅作参考。
  - 偏数值：五维 + 能力 + 装备 + 情绪修正参与判定，AI 按判定结果写剧情。
- 判定元数据展示在消息旁（如「力量 78 +5 愤怒加成 · 判定成功 87 vs 70」）。
- 战斗比重数值是"可调项"的代表：情绪敏感度、AI 自由度、装备生效比例等后续用同一滑块模式扩展。

## 7. 开演前 AI 预读取

点「开演」时先走读取确认流程（界面展示加载状态）：

```
AI 正在读取 → 世界观 ✓ → 角色卡 ✓ → 装备/道具 ✓ → Skills ✓ → 场景 ✓
全部读完 → 生成「共识摘要」（本场开局的既定事实）→ 才允许开演
```

- 目的：保证每个角色"知道"自己在什么世界、有什么装备、按什么风格演出，防止剧情崩坏。
- 共识摘要作为开场的 system context。

## 8. 直接输入（导演注入）

- 随时手动输入：推进剧情、加突发事件、指定角色行为、改写设定。
- AI 按指令执行，并与世界观约束校验（冲突时提示而非硬执行）。
- 沿用现有「注入」接口，在剧场界面强化为明显的输入区。

## 9. 幕后 AI 聊天窗口

- 剧场内新增「幕后」可折叠面板：直接与 AI 对话。
- 用途：讨论剧情走向、让 AI 起草世界观、补角色设定、指挥演出。
- 与演出消息流隔离，可随时展开/收起。
- 复用主对话的模型切换能力。

## 10. 现有代码整合

复用/扩展（不重写）：

| 现有模块 | 复用方式 |
|---|---|
| `src/roundtable/*` | 讨论模式的调度、轮次、结论逻辑 |
| `src/story/*` | 演绎模式的旁白、四通道、导演注入 |
| `src/characters/*` | 角色模型、情绪算法、记忆日志、单聊 |
| `src/skills/*` | Skills 存储、CRUD、加载（写作风格定位） |
| `src/web/*` | 路由、WS 推送、事件总线 |
| 前端人物库/模型切换 | 角色卡 UI、EntityModelSelect 等 |

新增模块：

- `src/theater/*`：剧场会话管理器（世界 + 模式 + 预读取 + 共识摘要）
- 世界数据模型（worldview.json）
- 角色卡扩展字段（stats/abilities/equipment/types）
- 战斗判定模块（数值计算 + 比重参数）
- 幕后聊天路由

## 11. 数据存储

- 世界：`E:\DeterminFlowData\worlds\<world_id>.json`
- 角色：现有 `E:\DeterminFlowData\characters\`（扩展字段）
- 剧场会话：`E:\DeterminFlowData\sessions\th-*.json`
- Skills：现有 `E:\DeterminFlowData\skills\`

## 12. 测试与验证

- 情绪算法：给定三我与情绪状态，验证输出行为倾向与判定修正。
- 战斗判定：不同五维/装备/情绪下，判定结果符合预期且比重滑块生效。
- 世界观约束：注入与世界观冲突的指令时，AI 提示冲突而非硬执行。
- AI 预读取：开演前必须完成读取并生成共识摘要。
- 回归：讨论模式（原圆桌）与演绎模式（原故事）原有功能不退化。
